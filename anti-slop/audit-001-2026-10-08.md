# Audit 001 - 2026-10-08

Cakupan: autentikasi, guard route, dan batas kewenangan akses. Tidak ada kode aplikasi yang diubah.

## Findings

1. **TINGGI - Route group admin belum memiliki guard login maupun role**
   - Bukti: `src/app/(admin)/layout.tsx:3-13` merender semua halaman admin tanpa memanggil `getServerSession`, mengecek `session.user.role`, atau melakukan redirect.
   - Dampak: request tanpa login dapat mengakses `/dashboard`, `/warga`, `/pengaturan`, dan halaman admin lainnya. User `WARGA` yang sudah login juga dapat masuk ke area admin.
   - Aturan: C-4 (ketahanan dan batas keamanan harus tetap berlaku pada setiap kondisi).
   - Perbaikan yang disarankan setelah disetujui: tambahkan satu guard admin di sisi server pada batas layout ini; redirect user yang belum login ke `/login` dan user non-admin ke `/portal`.

2. **TINGGI - Server action admin dapat dipanggil tanpa pemeriksaan kewenangan**
   - Bukti: `src/lib/actions/warga.ts:9-124`, `src/lib/actions/surat.ts:9-75`, `src/lib/actions/iuran.ts:8-72`, dan file action admin lainnya menulis ke Prisma tanpa membaca session atau mengecek role pemanggil.
   - Dampak: perlindungan route saja tidak cukup; request langsung ke Server Action dapat membuat, mengubah, atau menghapus data admin tanpa session admin.
   - Aturan: C-2 (setiap mutasi harus memiliki perilaku yang benar dan aman) dan C-4.
   - Perbaikan yang disarankan setelah disetujui: buat helper kecil `requireAdmin()` secara terpusat dan panggil di awal setiap mutasi admin menggunakan user yang sudah terautentikasi.

3. **TINGGI - Routing login dan root selalu mengarah ke dashboard admin**
   - Bukti: `src/app/(auth)/login/page.tsx:26-31` selalu menjalankan `router.push("/dashboard")`; `src/app/page.tsx:3-4` selalu redirect ke `/dashboard`.
   - Dampak: user `WARGA` diarahkan ke route admin, bukan `/portal`. Karena layout admin saat ini belum memiliki guard, area yang salah dapat tampil.
   - Aturan: C-4.
   - Perbaikan yang disarankan setelah disetujui: arahkan user berdasarkan role (`ADMIN -> /dashboard`, `WARGA -> /portal`) dan buat `/` menentukan tujuan berdasarkan session server, bukan redirect tetap.

4. **SEDANG - Halaman login belum memiliki guard untuk user yang sudah login**
   - Bukti: `src/app/(auth)/login/page.tsx:8-32` tidak mengecek session sebelum merender form.
   - Dampak: user dengan session yang masih valid dapat membuka `/login` secara manual dan tetap melihat form login; halaman ini juga tidak mempertahankan tujuan berdasarkan role.
   - Aturan: C-4.
   - Perbaikan yang disarankan setelah disetujui: ubah halaman menjadi server page, atau tambahkan server wrapper yang me-redirect user yang sudah login sebelum form client dirender.

5. **SEDANG - Layout portal belum membatasi akses hanya untuk WARGA**
   - Bukti: `src/app/(portal)/layout.tsx:3-10` tidak memiliki pemeriksaan session atau role. Halaman portal memang mengambil data secara kondisional, tetapi request tanpa login tidak selalu di-redirect.
   - Dampak: shell portal dapat dirender untuk user tanpa login maupun user `ADMIN`; kewenangan akses diserahkan ke masing-masing halaman atau action.
   - Aturan: C-4.
   - Perbaikan yang disarankan setelah disetujui: tambahkan guard `requireWarga()` pada batas layout portal dan pertahankan pemeriksaan session di level action sebagai perlindungan tambahan.

## Verifikasi

- `rg` memastikan tidak ada `src/middleware.ts`.
- `getServerSession` digunakan oleh halaman portal, portal action, dan API export, tetapi tidak digunakan oleh layout route group maupun mutasi admin.
- `npm run build` sudah dicoba, tetapi berhenti di `prisma generate` dengan error `EPERM` pada `node_modules/@prisma/client`. Ini merupakan masalah permission/environment, bukan diagnostic TypeScript atau Next.js.
