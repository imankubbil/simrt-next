# Audit 003 - 2026-10-11

Cakupan: pemeriksaan lanjutan setelah batch perbaikan sebelumnya. Audit ini hanya membaca kode; tidak ada kode aplikasi yang diubah.

## Prioritas tinggi

1. **P0 - Guard masih mempercayai role/status dari JWT yang bisa sudah lama**
   - Bukti: `requireAdmin()` dan layout portal membaca `session.user.role`, sementara strategi session di `src/lib/auth.ts` adalah `jwt`.
   - Dampak: perubahan role admin menjadi warga atau penonaktifan akun tidak langsung mencabut session yang sudah terbit.
   - Saran: pada guard server, ambil user terbaru dari database berdasarkan `session.user.id` lalu cek role/status; atau gunakan session database jika memang ingin pencabutan terpusat.

2. **P0 - Belum ada flow ganti/reset password dan perlindungan brute force**
   - Bukti: password warga dibuat tetap `warga123` di `src/lib/actions/warga.ts:35`, seed admin memakai `admin123`, dan `authorize()` tidak memiliki rate limit atau lockout.
   - Dampak: kredensial mudah ditebak dan endpoint login dapat dicoba berulang-ulang.
   - Saran: tambahkan password sementara + flag wajib ganti password, halaman ganti/reset password, serta rate limit sederhana per IP/NIK. Jangan menghapus default password sebelum flow penggantinya tersedia.

## Prioritas sedang

3. **P1 - Error database masih disamarkan sebagai data kosong**
   - Bukti: banyak halaman memakai `.catch(() => [])`, termasuk halaman admin dan portal.
   - Dampak: database bermasalah terlihat seperti tidak ada data; diagnosis dan pengalaman pengguna menjadi buruk.
   - Saran: hapus fallback global tersebut, log error, lalu sediakan `error.tsx` per route group dengan tombol coba lagi.

4. **P1 - Validasi Server Action belum merata**
   - Bukti: validasi Zod baru dipakai pada sebagian alur; action inventaris, kegiatan, mutasi, KK, pekerjaan, pengaturan, dan beberapa master data masih melakukan cast langsung dari `formData.get(...)`.
   - Dampak: request buatan dapat mengirim enum, angka, tanggal, ID relasi, atau string invalid yang tidak pernah melewati validasi UI.
   - Saran: buat schema Zod per action group dan validasi tepat setelah `requireAdmin()`.

5. **P1 - Transaction belum diterapkan ke semua mutasi multi-langkah**
   - Bukti: `updateWarga()` masih mengubah `User` lalu `Warga` dalam dua query terpisah; beberapa operasi KK dan master data juga terdiri dari lebih dari satu perubahan.
   - Dampak: kegagalan di tengah proses dapat meninggalkan data tidak sinkron.
   - Saran: bungkus mutasi yang saling bergantung dengan `prisma.$transaction`.

6. **P1 - Counter tahun surat belum digunakan**
   - Bukti: model `JenisSurat` memiliki `counterTahun`, tetapi `generateNomorSurat()` hanya memakai `counter` dan tahun berjalan.
   - Dampak: nomor surat berpotensi terus meningkat lintas tahun atau tidak mengikuti aturan penomoran tahunan.
   - Saran: tetapkan aturan reset counter tahunan secara eksplisit dan implementasikan dalam transaction.

7. **P1 - Secret auth belum fail-fast**
   - Bukti: `secret: process.env.NEXTAUTH_SECRET || process.env.AUTH_SECRET` dapat menghasilkan `undefined`.
   - Dampak: deployment salah konfigurasi baru gagal saat runtime dan sulit didiagnosis.
   - Saran: validasi environment saat startup/build dan dokumentasikan variable wajib.

## Prioritas rendah

8. **P2 - Belum ada regression test**
   - Bukti: `package.json` belum memiliki script test.
   - Saran: minimal uji akses anonymous/admin/warga, login warga nonaktif, direct Server Action tanpa role, dan counter surat bersamaan.

9. **P2 - Build/lint belum menjadi pemeriksaan yang stabil**
   - Bukti: `npm run build` sebelumnya berhenti pada `prisma generate` dengan `EPERM`; `npm run lint` mencoba memasang dependency TypeScript.
   - Saran: rapikan dependency install/lockfile dan tambahkan CI yang menjalankan `tsc`, lint, Prisma generate, serta build dari instalasi bersih.

10. **P2 - Responsiveness perlu diuji pada mobile**
   - Bukti awal: sidebar memakai lebar tetap `w-64`, portal menggunakan `h-screen`, dan beberapa tabel memakai `w-full` tanpa wrapper overflow yang terlihat.
   - Saran: lakukan click-through mobile; tambahkan menu collapse dan `overflow-x-auto` pada tabel jika memang diperlukan.

## Status Pengerjaan UI

Perbaikan UI sudah diterapkan:

- Sidebar admin dan portal sekarang menyusut menjadi navigasi ikon di mobile, dengan `aria-label` dan tooltip.
- Area konten memakai `min-w-0`, padding responsif, dan `overflow-auto` agar tidak memaksa layout desktop di layar kecil.
- Fokus keyboard global dibuat terlihat melalui `:focus-visible`.
- Loading state dan error state ditambahkan untuk route group admin dan portal.

Catatan: temuan error database (#3) belum sepenuhnya selesai. Error boundary sudah tersedia, tetapi fallback `.catch(() => [])` masih ada di beberapa halaman dan tetap perlu dihapus agar error database benar-benar sampai ke error state.

Temuan lain belum diperbaiki. Terapkan hanya nomor yang disetujui user.
