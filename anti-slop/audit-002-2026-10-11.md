# Audit 002 - 2026-10-11

Cakupan: rekomendasi perbaikan lanjutan setelah guard autentikasi dan role selesai. Audit ini hanya membaca kode; tidak ada kode aplikasi yang diubah.

## Prioritas tinggi

1. **P0 - Password default masih mudah ditebak**
   - Bukti: `src/lib/actions/warga.ts:33` selalu membuat password `warga123`; `prisma/seed.ts:9-10` memakai `admin123`.
   - Dampak: akun baru memiliki kredensial yang sama dan mudah diserang jika password tidak segera diganti.
   - Saran: buat password sementara acak sekali pakai, paksa ganti password saat login pertama, dan jangan menaruh password default di source code.
   - Aturan: C-4.

2. **P0 - Mutasi data penting belum atomik**
   - Bukti: pembuatan nomor surat membaca `counter`, menaikkan nilainya, lalu membuat surat secara terpisah di `src/lib/actions/surat.ts:49-68` dan `src/lib/actions/portal.ts:35-53`; `deleteWarga` juga menghapus dua tabel di `src/lib/actions/warga.ts:104-113` tanpa transaction.
   - Dampak: dua request bersamaan dapat menghasilkan nomor surat bentrok/terlewat, atau meninggalkan data setengah terhapus ketika salah satu operasi gagal.
   - Saran: gunakan `prisma.$transaction`; untuk counter gunakan update atomik dan pastikan `nomorSurat` tetap dilindungi constraint unik.
   - Aturan: C-4.

3. **P0 - Validasi input server belum memakai schema yang sudah tersedia**
   - Bukti: schema Zod ada di `src/lib/validators/warga.ts`, tetapi tidak digunakan (`safeParse`/`parse` tidak ditemukan). Server action masih melakukan cast langsung seperti `formData.get(...) as string`.
   - Dampak: input langsung ke Server Action dapat melewati validasi UI, menghasilkan data invalid, tanggal/angka `NaN`, atau enum yang tidak sah.
   - Saran: validasi `FormData` di setiap boundary action dengan schema Zod; jangan mempercayai tipe hasil cast dari `FormData`.
   - Aturan: C-2 dan C-4.

## Prioritas sedang

4. **P1 - Audit trail mencatat admin pertama, bukan admin yang sedang login**
   - Bukti: `src/lib/actions/surat.ts:46`, `iuran.ts:42`, `kegiatan.ts:38`, dan `mutasi.ts:24` memakai `findFirst({ role: "ADMIN" })`, lalu menyimpan `admin.id` sebagai `createdById`.
   - Dampak: riwayat pembuat data bisa salah ketika ada lebih dari satu admin.
   - Saran: gunakan `id` dari session yang dikembalikan `requireAdmin()`.
   - Aturan: C-5.

5. **P1 - Error database disamarkan sebagai data kosong**
   - Bukti: banyak halaman memakai `.catch(() => [])`, misalnya `src/app/(admin)/warga/page.tsx:10` dan halaman portal.
   - Dampak: database down atau query rusak terlihat seperti “belum ada data”, sehingga masalah operasional sulit ditemukan dan pengguna mendapat informasi yang salah.
   - Saran: tampilkan error state yang jelas dan log error; gunakan fallback kosong hanya untuk kondisi yang memang aman dianggap kosong.
   - Aturan: C-4 dan C-5.

6. **P1 - Status warga tidak ikut menjadi syarat login**
   - Bukti: `src/lib/auth.ts:14-34` memvalidasi NIK dan password, tetapi tidak memeriksa `warga.statusAktif` untuk role `WARGA`.
   - Dampak: warga yang sudah dinonaktifkan melalui data mutasi/status masih berpotensi login ke portal.
   - Saran: ambil relasi `warga` saat `authorize` dan tolak login warga yang tidak aktif.
   - Aturan: C-4.

## Prioritas rendah tetapi layak dirapikan

7. **P2 - Tipe session masih memakai `as any`**
   - Bukti: `src/lib/auth.ts:39,46-47`.
   - Saran: tambahkan module augmentation NextAuth untuk `Session.user`, `JWT`, dan `User`, sehingga `id` dan `role` bertipe resmi.

8. **P2 - Identitas user disimpan di field `email` sebagai NIK**
   - Bukti: `src/lib/auth.ts:30` mengisi `email: user.nik`, lalu banyak query mencari user berdasarkan `session.user.email`.
   - Saran: jadikan `session.user.id` sebagai sumber identitas utama; gunakan NIK hanya sebagai field login/tampilan.

9. **P2 - Belum ada pengujian regresi auth dan authorization**
   - Bukti: `package.json` tidak memiliki script test.
   - Saran: minimal tambahkan pengujian untuk empat alur: anonymous ke admin, warga ke admin, admin ke portal, dan direct call ke Server Action tanpa admin.
